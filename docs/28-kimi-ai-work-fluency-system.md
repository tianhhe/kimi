# Kimi AI工作力与内容教育体系 V1

更新日期：2026-07-02

## 1. 这份文档解决什么问题

前面的文档已经把增长策略、平台、栏目、脚本、达人、漏斗和模板搭起来了，但还有一个关键缺口：

Kimi 还需要一条比“功能教程”更高一层的教育主线。

Anthropic / Claude 真正在做的不是教用户几个 prompt，而是在教用户如何和 AI 一起完成复杂工作。所以 Kimi 的内容体系也不该只做“新手教程库”，而要做成一套 `AI工作力 -> 任务交付 -> 模板复用 -> 团队扩散` 的教育系统。

## 2. Kimi 应该卖什么能力

Kimi 不应只卖“更聪明的回答”，而应卖四类能力：

1. 把复杂任务说清楚的能力
2. 把散乱材料交给 AI 的能力
3. 把中间过程校准到可交付结果的能力
4. 把一次成功任务沉淀成模板、工作包和团队资产的能力

对应到社媒，不再是：

`功能介绍 -> 点赞收藏`

而是：

`真实任务 -> 正确委派 -> Kimi 执行 -> 人工验收 -> 可复用资产`

## 3. Kimi AI工作力框架

建议把 `Agent Fluency` 本地化成 `Kimi AI工作力`，固定成 6 个能力模块。

| 模块 | 用户要学会什么 | 典型错误 | Kimi 内容应该怎么教 |
|---|---|---|---|
| 任务定义 | 说清目标、对象、截止时间、输出格式 | 只说“帮我整理一下” | 错误问法 vs 正确 brief |
| 材料装配 | 提供资料、背景、样例、约束 | 没给材料就要完整结果 | 输入材料清单 |
| 计划审阅 | 先看步骤再让它做 | 一上来就要最终版 | 先计划后执行 |
| 中途校准 | 会补充上下文、纠偏、缩小范围 | 结果不对就直接放弃 | 二次迭代教学 |
| 结果验收 | 看引用、结构、空缺、风险 | 直接复制使用 | 验收清单 |
| 资产沉淀 | 把成功任务变模板、工作包、SOP | 每次从零开始 | 从案例到模板 |

## 4. 受众拆分要从 6 维升级到 8 维

建议至少按 8 个维度判断高付费受众：

| 维度 | 要回答的问题 | 为什么重要 |
|---|---|---|
| 公司阶段 | 个人、自由职业、小团队、SMB、大企业还是强监管组织？ | 决定预算、采购方式、治理诉求 |
| 职能部门 | 产品、PMM、增长、销售、CS、研究、财务、法务、HR、教育、内容还是管理层？ | 决定任务类型和语言风格 |
| 行业 | 金融、法律、教育、医疗、生命科学、政企、非营利、软件、内容等哪一类？ | 决定案例、风险和承接页 |
| 任务类型 | 研究、写作、表格、PPT、资料整合、流程自动化、客户沟通、合规审查等哪一类？ | 决定栏目和模板形态 |
| 材料复杂度 | 单文档、多文档、跨格式、长上下文、多系统协作到什么程度？ | 决定是否适合打 Kimi Work / Agent |
| 风险等级 | 低风险草稿、需人工复核、中高风险准确性任务属于哪一级？ | 决定验收清单和信任叙事 |
| 采用成熟度 | 尝鲜者、模板用户、workflow 用户、agent 委派者、团队推广者、管理员属于哪一级？ | 决定教育难度和 CTA |
| 购买触发 | 省时间、减返工、增收入、降风险、团队复用、截止期压力里哪一个最强？ | 决定付费文案和达人投放角度 |

## 5. 栏目体系先按职责分，再按平台映射

建议 Kimi 的长期栏目体系先分 4 条主线：

### 5.1 AI工作力

教用户怎么和 Kimi 协作，而不是只教功能。

### 5.2 Kimi for X

按角色/行业入口承接高意图人群，比如：

1. Kimi for 产品 / PMM / 增长
2. Kimi for 销售 / CS / BD
3. Kimi for 小团队老板
4. Kimi for 研究 / 咨询 / 投研
5. Kimi for 财务 / 法务 / HR / 合规
6. Kimi for 学生 / 教师 / 教育管理者

### 5.3 一件事交给Kimi

每条内容固定结构：

`原始任务 -> 输入材料 -> Kimi执行 -> 中途校准 -> 最终交付 -> 验收方式`

### 5.4 模板 / 工作包 / 微课

把内容沉淀成资产，每个工作包至少包含：

1. 使用场景
2. 输入材料清单
3. 标准 prompt
4. 输出样例
5. 验收标准
6. 常见失败原因

## 6. GTM 承接链路

新功能不要只做：

`发布公告 -> 发几条内容 -> 看播放`

而要做：

`内容 -> 任务卡 -> 模板/工作包 -> 首个高价值任务 -> D7复用 -> 团队扩散`

## 7. 一类必须做的内容

`哪些任务不该直接交给Kimi`

这是高付费用户信任建立的一部分，不是负面内容。固定可以做成长期栏目：

1. 哪些结果必须人工复核
2. 哪些场景必须提供原文来源
3. 哪些结论必须二次验证
4. 哪些高风险任务只适合先出草稿
5. 团队部署前要问的 10 个治理问题

## 8. 配套动作

基于这份文档，Kimi 接下来最该优先补的是：

1. `Kimi AI工作力` 栏目
2. `Kimi for X` 系列入口页和栏目
3. `一件事交给Kimi` 的交付型脚本系列
4. `工作包库 / 用例库` 两张长期表
5. `哪些任务不该直接交给Kimi` 的信任栏目
