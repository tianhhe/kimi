# Kimi 社媒增长总纲

更新日期：2026-07-02

## 1. 增长定位

Kimi 在社媒上的主定位：复杂工作交付系统。

不是只强调“AI 聊天”“长上下文”“搜索总结”，而是把 Kimi 展示为能帮助用户完成真实工作的协作系统：读材料、拆任务、查证、生成、迭代、交付。

一句话表达：

> 把一堆资料、一个模糊目标、一个紧急任务，交给 Kimi 变成可用成果。

## 2. 增长目标

社媒不是单纯做声量，而是承担 4 个业务目标：

| 目标 | 解释 | 社媒动作 |
|---|---|---|
| 建认知 | 让用户知道 Kimi 适合复杂任务 | 场景案例、行业教程、对比内容 |
| 促首用 | 让用户第一次把真实材料交给 Kimi | 模板、prompt、任务挑战 |
| 促高价值任务 | 让用户完成一次有结果的长任务 | 分步骤教程、直播演示、案例复盘 |
| 建口碑 | 让用户愿意分享自己的 Kimi 工作流 | UGC 征集、达人共创、结果展示 |

## 3. 目标人群

优先人群不是“所有 AI 用户”，而是有复杂任务压力、结果可验证、愿意为减少返工或提升交付质量付费的人。完整受众矩阵见 `docs/23-kimi-audience-segmentation-v2.md` 和 `templates/audience-segment-matrix-v2.csv`。

| 优先级 | 人群 | 高压任务 | 内容入口 | 转化动作 |
|---|---|---|---|---|
| P0 | 小团队老板/创始人 | 经营周报、投资人 update、客户跟进、招聘、增长计划 | 一人多岗、经营工作流、小团队 AI 工作台 | 完成一份经营周报或投资人 update |
| P0 | 产品/PMM/增长负责人 | 竞品、GTM、用户反馈聚类、路线图证据 | 产品分析、功能发布、增长策略、案例库 | 输出 GTM brief 或路线图证据表 |
| P0 | 销售/BD/CS 管理者 | 客户研究、拜访提纲、异议处理、续费复盘 | 客户风险表、销售话术、续费行动包 | 生成客户拜访或续费行动包 |
| P0 | 咨询/投研/战略 | 行业研究、公司对比、访谈提纲、memo、deck | 行业预诊断、投研 memo、咨询交付物 | 生成一份行业预诊断或 memo |
| P0 | 财务/法务/HR/运营支持 | 合同摘要、制度 FAQ、预算复盘、入职计划、SOP | 内部运营工作流、风险校验、团队模板 | 保存为团队 SOP 或模板库 |
| P0 | 受监管行业专业人群 | 尽调、合规、文献摘要、风险审查、研究记录 | 金融/医疗/法律/生命科学资料工作流 | 使用验收清单完成高风险任务 |
| P1 | 研究生/科研助理 | 论文、文献、开题、答辩、访谈资料 | 文献综述、论文框架、研究资料整理 | 上传材料并生成论文/研究框架 |
| P1 | 求职/转岗人群 | 简历、面试、岗位匹配、作品集 | 简历诊断、面试模拟、JD 解析 | 完成一版岗位定制简历 |
| P1 | 内容创作者/代理商 | 选题、脚本、素材审计、账号复盘、客户 brief | 选题拆解、爆款复盘、脚本共创 | 生成可发布内容脚本或栏目表 |
| P2 | 泛办公/普通学生/个人生活用户 | 周报、会议纪要、学习计划、生活规划 | 低门槛模板、轻任务演示 | 完成首个轻量任务并进入模板复用 |

## 4. 核心叙事

### 4.1 从功能到任务

不要说：Kimi 支持长上下文、联网搜索、文件阅读。

要说：把 20 页材料变成汇报提纲；把一堆竞品页面变成 GTM 计划；把岗位 JD 和过往经历变成定制简历。

### 4.2 从演示到交付

每条内容都要尽量出现“输入 - 过程 - 输出”：

| 环节 | 要展示什么 |
|---|---|
| 输入 | 用户真实会遇到的材料、问题、限制 |
| 过程 | Kimi 如何拆解、追问、生成、校验 |
| 输出 | 文档、表格、脚本、计划、清单、可复制模板 |

### 4.3 从工具到工作流

所有内容都优先沉淀为可复用工作流：

1. 场景卡：这个场景谁会遇到，痛点是什么。
2. 操作步骤：打开 Kimi 后怎么做。
3. Prompt 模板：用户可以复制。
4. 结果样例：最后应该长什么样。
5. 进阶动作：如何继续迭代。

## 5. 渠道分工

| 渠道 | 角色 | 内容形态 | 主指标 |
|---|---|---|---|
| 小红书 | 场景种草和教程沉淀 | 图文教程、清单、模板 | 收藏率、主页点击、模板领取 |
| 抖音/视频号 | 强演示和破圈 | 前后对比、屏幕录制、真人讲解 | 完播率、评论提问、转化点击 |
| B 站 | 深度教学和信任建设 | 长教程、案例复盘、直播切片 | 播放时长、关注、站外搜索 |
| 知乎 | 场景解释和搜索承接 | 问答、长文、横评 | 搜索曝光、赞藏、链接点击 |
| 即刻/微博 | 节点扩散和社群讨论 | 产品更新、案例金句、互动 | 转发、评论、话题参与 |

## 6. 月度运营节奏

| 周期 | 重点 | 产出 |
|---|---|---|
| 第 1 周 | 定目标、定栏目、定达人池 | 月度目标表、内容排期、达人名单 |
| 第 2 周 | 强执行和 A/B 测试 | 20-40 条内容、3-5 个实验 |
| 第 3 周 | 放大有效场景 | 爆款拆解、达人二次 brief、直播/活动 |
| 第 4 周 | 复盘和资产化 | 周/月复盘、模板库更新、竞品库更新 |

## 7. 运营原则

1. 每条内容必须对应一个真实任务，不做抽象功能介绍。
2. 每个栏目必须能沉淀模板，不做一次性灵感。
3. 每个达人合作必须交付脚本和结果截图，不只买曝光。
4. 每周必须保留失败样本，失败内容是下周选题校准的依据。
5. 每月必须形成一个可复用资产包，例如“毕业论文 Kimi 工作流”“市场调研 Kimi 工作流”。

## 8. 从 Claude 和竞品反推的升级版打法

### 8.1 把“会用 Kimi”做成用户教育体系

参考 Claude 的 AI Fluency 和 Claude 101，Kimi 应建立自己的 `Agent Fluency`：

| 用户能力 | Kimi 教育内容 |
|---|---|
| 会委派 | 给 Kimi 目标、材料、限制、输出格式 |
| 会描述 | 不只问一句，而是提供上下文和判断标准 |
| 会判断 | 用追问、校验、对比让结果更可靠 |
| 会迭代 | 把第一次回答推进到可交付文档 |

### 8.2 把 Kimi Agent / Kimi Work 包装成任务循环

固定表达：目标 -> 计划 -> 执行 -> 校验 -> 交付。

每个新功能 GTM 都按这 5 步写内容，而不是只说功能名。比如 Agent Swarm 不说“多 agent 并行”，而说“一个 agent 查资料，一个 agent 做表格，一个 agent 写报告，最后合成一份老板能看的市场调研”。

### 8.3 高付费人群优先级

高付费人群按 6 个维度判断：公司规模、部门/职能、行业、任务类型、付费触发、采用成熟度。评分方法见 `docs/23-kimi-audience-segmentation-v2.md`。

| 优先级 | 人群 | 为什么优先 |
|---|---|---|
| P0 | 小团队老板、产品/PMM/增长、销售/CS、咨询/投研、财务/法务/HR、受监管行业、团队推广者 | 任务复杂、时间贵、结果影响收入/风险/决策，且容易形成团队复用 |
| P1 | 研究生/科研、求职/转岗、创作者/代理商、教师/培训师、自由职业者、开发者/自动化用户 | 节点明确、模板需求强、适合社媒种草，但付费触发需要靠任务场景拉高 |
| P2 | 泛办公白领、普通学生、个人生活用户、AI 尝鲜用户 | 规模大但付费意愿分化，适合作为模板养成和品牌扩散池 |

### 8.4 社媒内容的最低交付标准

一条内容如果不能回答下面 4 个问题，就不发：

1. 这是谁的真实任务？
2. Kimi 读了什么材料或接收了什么上下文？
3. Kimi 怎么从目标推进到结果？
4. 用户看完后能不能立刻复制一个模板去试？
