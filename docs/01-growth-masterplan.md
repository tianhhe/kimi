# Kimi 社媒增长总纲

更新日期：2026-07-02

## 1. 增长定位

Kimi 在社媒上的主定位：复杂工作交付系统。

不是只强调“AI 聊天”“长上下文”“搜索总结”，而是把 Kimi 展示为能帮助用户完成真实工作的协作系统：读材料、拆任务、查证、生成、迭代、交付。

一句话表达：

> 把一堆资料、一个模糊目标、一个紧急任务，交给 Kimi 变成可用成果。

## 2. 增长目标

社媒不是单纯做声量，而是承担 4 个业务目标：

| 目标 | 解释 | 社媒动作 |
|---|---|---|
| 建认知 | 让用户知道 Kimi 适合复杂任务 | 场景案例、行业教程、对比内容 |
| 促首用 | 让用户第一次把真实材料交给 Kimi | 模板、prompt、任务挑战 |
| 促高价值任务 | 让用户完成一次有结果的长任务 | 分步骤教程、直播演示、案例复盘 |
| 建口碑 | 让用户愿意分享自己的 Kimi 工作流 | UGC 征集、达人共创、结果展示 |

## 3. 目标人群

优先人群不是“所有 AI 用户”，而是有复杂任务压力的人。

| 人群 | 高压任务 | 内容入口 | 转化动作 |
|---|---|---|---|
| 学生/研究生 | 论文、文献、考试、申请材料 | 学习工作流、资料总结、答辩准备 | 上传材料并生成学习/论文框架 |
| 职场白领 | 周报、方案、会议纪要、行业研究 | 办公效率、报告生成、信息整理 | 用模板完成一份真实工作文档 |
| 内容创作者 | 选题、脚本、资料收集、改稿 | 选题拆解、爆款复盘、脚本共创 | 生成一条可发布内容脚本 |
| 求职人群 | 简历、面试、岗位匹配、作品集 | 简历诊断、面试模拟、JD 解析 | 完成一版岗位定制简历 |
| 产品/运营/市场 | 竞品、GTM、用户分析、增长计划 | 产品分析、增长策略、案例库 | 输出一份可执行计划 |

## 4. 核心叙事

### 4.1 从功能到任务

不要说：Kimi 支持长上下文、联网搜索、文件阅读。

要说：把 20 页材料变成汇报提纲；把一堆竞品页面变成 GTM 计划；把岗位 JD 和过往经历变成定制简历。

### 4.2 从演示到交付

每条内容都要尽量出现“输入 - 过程 - 输出”：

| 环节 | 要展示什么 |
|---|---|
| 输入 | 用户真实会遇到的材料、问题、限制 |
| 过程 | Kimi 如何拆解、追问、生成、校验 |
| 输出 | 文档、表格、脚本、计划、清单、可复制模板 |

### 4.3 从工具到工作流

所有内容都优先沉淀为可复用工作流：

1. 场景卡：这个场景谁会遇到，痛点是什么。
2. 操作步骤：打开 Kimi 后怎么做。
3. Prompt 模板：用户可以复制。
4. 结果样例：最后应该长什么样。
5. 进阶动作：如何继续迭代。

## 5. 渠道分工

| 渠道 | 角色 | 内容形态 | 主指标 |
|---|---|---|---|
| 小红书 | 场景种草和教程沉淀 | 图文教程、清单、模板 | 收藏率、主页点击、模板领取 |
| 抖音/视频号 | 强演示和破圈 | 前后对比、屏幕录制、真人讲解 | 完播率、评论提问、转化点击 |
| B 站 | 深度教学和信任建设 | 长教程、案例复盘、直播切片 | 播放时长、关注、站外搜索 |
| 知乎 | 场景解释和搜索承接 | 问答、长文、横评 | 搜索曝光、赞藏、链接点击 |
| 即刻/微博 | 节点扩散和社群讨论 | 产品更新、案例金句、互动 | 转发、评论、话题参与 |

## 6. 月度运营节奏

| 周期 | 重点 | 产出 |
|---|---|---|
| 第 1 周 | 定目标、定栏目、定达人池 | 月度目标表、内容排期、达人名单 |
| 第 2 周 | 强执行和 A/B 测试 | 20-40 条内容、3-5 个实验 |
| 第 3 周 | 放大有效场景 | 爆款拆解、达人二次 brief、直播/活动 |
| 第 4 周 | 复盘和资产化 | 周/月复盘、模板库更新、竞品库更新 |

## 7. 运营原则

1. 每条内容必须对应一个真实任务，不做抽象功能介绍。
2. 每个栏目必须能沉淀模板，不做一次性灵感。
3. 每个达人合作必须交付脚本和结果截图，不只买曝光。
4. 每周必须保留失败样本，失败内容是下周选题校准的依据。
5. 每月必须形成一个可复用资产包，例如“毕业论文 Kimi 工作流”“市场调研 Kimi 工作流”。

## 8. 从 Claude 和竞品反推的升级版打法

### 8.1 把“会用 Kimi”做成用户教育体系

参考 Claude 的 AI Fluency 和 Claude 101，Kimi 应建立自己的 `Agent Fluency`：

| 用户能力 | Kimi 教育内容 |
|---|---|
| 会委派 | 给 Kimi 目标、材料、限制、输出格式 |
| 会描述 | 不只问一句，而是提供上下文和判断标准 |
| 会判断 | 用追问、校验、对比让结果更可靠 |
| 会迭代 | 把第一次回答推进到可交付文档 |

### 8.2 把 Kimi Agent / Kimi Work 包装成任务循环

固定表达：目标 -> 计划 -> 执行 -> 校验 -> 交付。

每个新功能 GTM 都按这 5 步写内容，而不是只说功能名。比如 Agent Swarm 不说“多 agent 并行”，而说“一个 agent 查资料，一个 agent 做表格，一个 agent 写报告，最后合成一份老板能看的市场调研”。

### 8.3 高付费人群优先级

| 优先级 | 人群 | 为什么优先 |
|---|---|---|
| P0 | 产品/运营/市场、咨询/商业分析、小团队经营者 | 交付压力高、时间贵、愿意为结果付费 |
| P1 | 内容创作者、求职/留学/研究生 | 节点明确、模板需求强、容易被社媒种草 |
| P2 | 泛办公白领、学生泛学习 | 规模大但付费意愿分化，需要用模板和任务养成 |

### 8.4 社媒内容的最低交付标准

一条内容如果不能回答下面 4 个问题，就不发：

1. 这是谁的真实任务？
2. Kimi 读了什么材料或接收了什么上下文？
3. Kimi 怎么从目标推进到结果？
4. 用户看完后能不能立刻复制一个模板去试？
