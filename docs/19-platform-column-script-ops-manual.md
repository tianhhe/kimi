# Kimi 平台-栏目-选题-脚本运营手册

更新日期：2026-07-02

适用阶段：第 2 月社媒增长运营。目标是把第 1 月建立的 Kimi Work 101、Agent Fluency、岗位工作流和模板资产，继续落到平台专属栏目、可排期选题、可改写脚本、评论承接、功能使用追踪和周复盘。

## 0. 双站点资产理解

内容体系要按 Claude/Anthropic 的双站点逻辑来理解：

| 参照站点 | 内容职责 | Kimi 对应层 | 社媒内容要回流的资产 |
|---|---|---|---|
| Anthropic.com | 公司级内容资产，建立可信度、研究感、企业级叙事和长期观点 | Kimi 公司级内容资产层 | AI 工作方式中心、信任与安全中心、研究/方法论文章、企业级客户故事、行业趋势报告 |
| claude.com | 产品转化资产，承接功能、行业、课程、插件、客户案例和具体使用路径 | Kimi 产品转化资产层 | Kimi Work 功能页、Kimi Agent 课程页、行业工作流落地页、模板库、案例库、功能插件/扩展页 |

社媒不是独立选题池，而是站点资产的分发和验证系统。每条内容必须绑定 4 个承接字段：

1. 站点层：公司级内容资产层，或产品转化资产层。
2. 落地页：用户点击后进入的具体页面或计划沉淀的页面。
3. 模板库：用户可以复制的任务模板、工作流模板或行业包。
4. 案例库：内容验证成功后沉淀成的用户案例、行业案例或高付费场景案例。

第 2 月的资产链路是：

`社媒栏目 -> 选题/脚本 -> 落地页 -> 模板库/案例库 -> 产品功能激活 -> 站点资产更新`

## 1. 整体增长策略

第 2 月不再只证明“Kimi 可以做复杂任务”，而是证明“不同高价值人群可以稳定把 Kimi 用进自己的工作流”。内容主线从泛教育进入功能渗透和付费意图判断。

| 层级 | 运营目标 | 内容抓手 | 数据判断 |
|---|---|---|---|
| 认知 | 让用户知道 Kimi Work 不是普通聊天 | 真实任务拆箱、输入到交付物、功能场景卡 | 完播率、阅读完成、收藏 |
| 理解 | 让用户知道 Kimi Agent 如何参与复杂任务 | Agent 分工图、Task Loop、人工介入边界 | 评论问题、私信需求、长文赞藏 |
| 首用 | 让用户开始第一个高价值任务 | 模板包、任务卡、社群打卡 | 关键词评论、模板领取、到站点击 |
| 完成 | 让用户 7 日内产出文档、表格、PPT、网页、报告 | 工作流教程、案例复盘、直播答疑 | 首次任务率、高价值任务完成率 |
| 复用 | 让团队或高付费人群形成固定流程 | 团队 SOP、行业包、月度模板包 | D7 回访、功能留存、升级点击 |

北极星指标沿用：社媒带来的 7 日内高价值任务完成用户数。

第 2 月的运营闭环是：

`平台定位 -> 栏目供给 -> 站点资产映射 -> 选题排期 -> 脚本生产 -> 发布分发 -> 评论承接 -> 功能追踪 -> 周复盘 -> 站点资产更新 -> 下周调度`

### 1.1 第 2 月内容配比

| 内容方向 | 占比 | 主要功能 | 目标人群 |
|---|---:|---|---|
| Kimi Agent 实战 | 25% | Kimi Agent、Agent Swarm、Deep Research | 产品、市场、咨询、研究 |
| Kimi Work 交付链路 | 25% | Kimi Work、Docs、Slides、Sheets、Websites | 职场高频交付人群 |
| 功能渗透场景 | 20% | Scheduled Tasks、Docs、Slides、Sheets、Websites | 内容团队、小团队、运营 |
| 高付费人群工作流 | 20% | Kimi Work、Agent、Deep Research、团队模板 | 管理者、创始人、销售、咨询、PMM |
| 信任与复盘 | 10% | 校验、引用、权限、周复盘 | 团队负责人、知识工作者 |

### 1.2 运营原则

1. 每条内容必须有一个真实任务、一个明确输入、一个可展示结果。
2. 每条内容必须绑定至少一个功能，不发布纯概念内容。
3. 每条内容必须绑定站点层、落地页、模板库和案例库，不发布无承接内容。
4. 每个平台使用专属栏目，不把同一标题机械搬运。
5. 每周至少有 1 条内容进入社群任务卡，验证用户是否真的能完成。
6. 每周五复盘时，先看高价值任务完成，再看曝光和互动。

## 6. 发布 SOP

| 步骤 | 负责人 | 产出 | 质量标准 |
|---|---|---|---|
| 选题入池 | 内容负责人 | 选题卡 | 有平台、栏目、人群、功能、交付物 |
| 脚本初稿 | 编导/作者 | 脚本骨架 | 有钩子、输入、过程、结果、CTA |
| 素材准备 | 作者/设计 | 截图、录屏、模板 | 至少有输入截图和结果截图 |
| 功能映射 | PMM/数据 | 功能追踪字段 | 明确主功能、成功事件和链接参数 |
| 站点承接 | PMM/站点负责人 | 落地页、模板库、案例库字段 | 明确公司级资产或产品转化资产，不让社媒内容悬空 |
| 发布排期 | 渠道负责人 | 日历 | 每周覆盖 8 个渠道，不低于 40 条/月 |
| 上线检查 | 渠道负责人 | 发布链接 | 标题、封面、CTA、评论置顶、链接参数完整 |
| 数据回收 | 数据/渠道 | 48 小时和 7 日数据 | 回收曝光、有效观看、互动、到站、功能激活 |

### 6.1 发布前检查清单

1. 标题是否包含任务或结果，而不是只有功能名。
2. 首屏是否能看懂“谁在什么场景下得到什么结果”。
3. CTA 是否只有一个，且和平台习惯一致。
4. 评论区置顶是否准备好关键词和领取方式。
5. 模板页或落地页是否能记录来源平台、栏目、功能。
6. 站点资产是否准备好接住用户：落地页、模板库、案例库是否命名一致。
7. 是否有社群承接任务卡。

## 7. 评论承接 SOP

评论区不是互动装饰，而是下一步转化入口。每条内容发布后 2 小时内完成第一轮承接，24 小时内完成需求归类，周五进入复盘。

| 评论类型 | 判断 | 回复动作 | 后续动作 |
|---|---|---|---|
| 关键词领取 | 用户已经有模板意图 | 回复领取方式，私信或引导落地页 | 记录模板领取和来源栏目 |
| 场景提问 | 用户有真实任务但不会拆 | 追问目标、材料、结果格式 | 收进“评论改任务”栏目 |
| 功能困惑 | 用户不理解 Work/Agent/功能入口 | 用一句场景解释功能 | 补 FAQ 或短视频 |
| 质疑效果 | 用户担心质量、安全、校验 | 给边界和校验方法 | 收进信任内容选题 |
| 付费咨询 | 用户问团队、权限、价格、复杂任务 | 私信承接或预约拆解 | 标记高意向线索 |
| UGC 晒图 | 用户已经完成任务 | 表扬具体结果，询问授权 | 改成用户案例 |

评论复用规则：

1. 每周从评论区选 10 条真实需求，改写成下周选题。
2. 每周从社群选 3 个完成案例，进入官方案例库。
3. 每条高频困惑至少对应 1 条 FAQ 或解释内容。
4. 高意向线索必须标记来源平台、栏目、功能和任务类型。

## 8. 功能使用追踪

每条内容都要在 brief、排期表和复盘表里填写功能映射。功能追踪不只看点击，更看是否完成高价值任务。

| 字段 | 填写方式 | 示例 |
|---|---|---|
| content_id | 平台-栏目-日期-序号 | xhs-task-unbox-w2-03 |
| platform | 平台 | 小红书 |
| column | 栏目 | 高价值任务拆箱 |
| site_layer | 站点层 | 产品转化资产层 |
| landing_page | 落地页 | Kimi Work 入门页 |
| template_library | 模板库 | 任务卡模板库 |
| case_library | 案例库 | 用户交付物案例库 |
| primary_feature | 主功能 | Kimi Work |
| secondary_feature | 辅助功能 | Docs、Sheets |
| target_audience | 目标人群 | 产品经理 |
| funnel_goal | 漏斗目标 | 评论关键词 -> 模板领取 -> 首次任务 |
| success_event | 成功事件 | 7 日内完成竞品矩阵 |
| cta | 行动入口 | 评论“竞品”领模板 |
| review_action | 复盘动作 | 加码、重写 CTA、转长文、进社群 |

### 8.1 功能追踪口径

| 功能 | 内容触发 | 激活事件 | 高价值完成事件 | 常见阻塞 |
|---|---|---|---|---|
| Kimi Work | 资料夹到交付物、任务卡、模板库 | 创建或进入 Work 任务 | 保存文档、表格、PPT、网页或报告 | 用户不知道如何描述任务 |
| Kimi Agent | Agent 分工、Task Loop、人工介入 | 启动 Agent 任务 | Agent 产出可合并的阶段结果 | 用户把 Agent 当自动聊天 |
| Agent Swarm | 多角色分工、并行调研 | 使用多 Agent 或并行任务 | 多 Agent 结果合成一个交付物 | 任务拆分过细或过泛 |
| Deep Research | 行业调研、证据表、反证 | 发起深度研究 | 输出带来源的研究结论 | 用户不检查来源 |
| Docs | 方案、周报、SOP、邮件 | 生成或编辑文档 | 文档被保存、复制、导出 | 输出格式不明确 |
| Sheets | 竞品矩阵、复盘表、销售表 | 生成或分析表格 | 表格被保存、下载或二次分析 | 字段设计不清楚 |
| Slides | 汇报大纲、培训课、投资人更新 | 生成 PPT 或大纲 | 大纲被保存或导出 | 听众和目标不清楚 |
| Websites | 活动页、复盘页、作品集 | 生成网页或页面结构 | 页面被预览、保存或分享 | 用户以为只能写文章 |
| Scheduled Tasks | 周报提醒、客户跟进、竞品追踪 | 创建定时任务 | 定时任务触发并被查看 | 触发频率和输出标准不清楚 |

## 9. 周复盘

周复盘固定在每周五进行，输出必须能直接改下周排期。

### 9.1 周复盘议程

| 环节 | 问题 | 输出 |
|---|---|---|
| 平台表现 | 哪个平台贡献最多高价值任务完成 | 平台加码/降频名单 |
| 栏目表现 | 哪个栏目收藏高但任务完成低 | CTA 或模板入口调整 |
| 功能渗透 | 哪个功能曝光高但激活低 | 功能包装重写方向 |
| 人群质量 | 哪类人群带来付费意图 | 下周高付费场景加码 |
| 评论反馈 | 哪些评论说明用户没理解 Kimi | FAQ 和解释内容 |
| 社群结果 | 哪些任务真的完成了 | 官方案例和达人 brief |
| 站点资产 | 哪些社媒内容需要沉淀到落地页、模板库、案例库 | 本周站点更新清单 |
| 下周排期 | 停止、调整、加码、资产化什么 | 更新内容日历和 scorecard |

### 9.2 决策规则

| 数据信号 | 判断 | 下周动作 |
|---|---|---|
| 高收藏 + 高模板领取 + 高任务完成 | 内容和承接成立 | 做系列、投达人、沉淀长文 |
| 高收藏 + 低任务完成 | 用户觉得有用但没有动手 | 增加步骤图、录屏、社群打卡 |
| 高完播 + 低搜索/点击 | 视频好看但 CTA 弱 | 改开头承诺和结尾入口 |
| 高功能点击 + 低功能完成 | 产品上手或教程卡住 | 补教程、FAQ、直播答疑 |
| 高评论提问 + 低模板领取 | 场景有兴趣但模板不对 | 重写模板字段 |
| 高付费人群私信多 | 商业化信号成立 | 增加行业包和团队 SOP |
| 社群任务完成高 | 场景真实有效 | 改成平台案例和公众号资产 |

### 9.3 每周交付物

1. 一页平台表现表。
2. 一页栏目 scorecard 更新。
3. 10 条评论需求改写选题。
4. 3 个社群完成案例。
5. 本周新增或更新的落地页、模板库、案例库清单。
6. 下周 10 条加码内容、5 条停止或重写内容。
7. 下周主推功能和主推高付费场景。
