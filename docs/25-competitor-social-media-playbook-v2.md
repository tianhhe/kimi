# Kimi 竞品社媒观察与反制打法 v2

更新日期：2026-07-02

本文件只解决一个问题：竞品正在怎样把“AI agent / 工作台 / 知识工作自动化”讲给市场听，Kimi 应该怎样持续观察、拆解、反制，并转成官方账号内容、达人投放和 tracker 里的可执行动作。

重点竞品：Claude / Claude Cowork、OpenAI Codex、Trae Work、Qoder Work、WorkBuddy。

核心结论：Kimi 不要被拖进“谁更像 coding agent”的单点战场。Kimi 最应该抢的是“中文复杂知识工作交付台”：把网页、PDF、表格、会议记录、客户资料、竞品材料、运营数据交给 Kimi，拿回报告、表格、PPT、方案、合同审阅清单、销售拜访包、运营复盘和团队管理动作。

## 1. 本轮证据边界

### 已核对的公开线索

| 类型 | 已核对来源 | 主要用途 |
|---|---|---|
| 本地资料 | `docs/18-competitor-gtm-social-deep-dive.md`、`docs/10-social-channel-title-swipe.md`、`templates/competitor-tracker.csv` | 复用已有竞品框架、标题库和 tracker 字段 |
| Claude / Cowork | Claude Cowork 产品页、Claude plugins、Anthropic Learn / Claude for Work / AI Fluency、Claude Help Center | 判断其教育阵地、插件/技能包装、知识工作任务表达 |
| OpenAI Codex | OpenAI Academy “How to use Codex for everyday work”、Codex for work、Codex for every role/tool/workflow、Developers use cases | 判断 Codex 非代码化扩张和“everyday work”内容结构 |
| Trae Work | TRAE LinkedIn “Introducing Design Mode in TRAE Work”、TRAE 官网/YouTube 公开搜索结果 | 判断 Work -> Design -> Code 的闭环叙事 |
| Qoder Work | QoderWork 官网、Qoder docs、Alibaba Cloud marketplace、LinkedIn / YouTube 公开搜索结果 | 判断“Describe it. Automate it. Deliver it.”与耗时对比打法 |
| WorkBuddy | Tencent Cloud WorkBuddy 页、Tencent Cloud Techpedia、Tencent 官方文章、Tencent Cloud LinkedIn / X 公开搜索结果 | 判断“AI employee / 100+ experts / IM remote control / deliverable”打法 |

### 证据不足处

1. X、LinkedIn、YouTube 可通过搜索结果和公开页面观察标题、账号定位和部分帖子，但完整时间线、互动数据、广告投放数据无法稳定访问，不能编造具体播放量、转评赞和投放预算。
2. B站上能看到大量搬运、教程和第三方解读，未稳定确认 Claude / OpenAI / Qoder / WorkBuddy 在 B站有持续运营的官方主账号。Trae 有更明显的中文视频教程线索，但仍需人工进入账号页二次核验。
3. 公众号生态搜索结果不完整，尤其 WorkBuddy / 腾讯云相关内容可能分散在腾讯云、腾讯研究院、媒体号和代理商号里，本文只把它作为待补采渠道，不写未经核实的具体标题。
4. 竞品产品功能、页面和社媒标题在 2026 年变化很快。每周 tracker 应把“发布日期、来源 URL、是否官方、是否已二次验证”作为强制字段。

## 2. 竞品社媒打法总览

| 竞品 | 主阵地 | 社媒心智 | 最像什么栏目 | Kimi 的反制入口 |
|---|---|---|---|---|
| Claude / Cowork | 官网产品页、Learn / Academy、Help Center、LinkedIn、YouTube、X | 会用 AI 是一种职业能力；Cowork 把 Claude 放进真实文件、工具和多步任务 | AI Fluency、Claude 101、Claude for Work、Cowork plugins、行业工作流 | Kimi Work 101、中文 Agent Fluency、岗位任务包、从资料到交付物 |
| OpenAI Codex | OpenAI 官网、OpenAI Academy、Developers use cases、OpenAI / Developers 社媒 | Codex 从 coding agent 扩展成所有角色的生产力工具，非开发者也能用 | Everyday work、role-specific plugins、Sites、annotations、productivity use cases | “非程序员也能交给 Kimi 的 10 类工作” |
| Trae Work | TRAE 官网、LinkedIn、YouTube、Reddit、B站教程 | 从想法到设计到代码的一站式产品生产线 | Work Mode -> Design Mode -> Code Mode、SOLO、ship faster | 避开纯构建，抢“产品/运营/市场在写 PRD 前后的知识工作” |
| Qoder Work | Qoder 官网、docs、Alibaba Cloud、LinkedIn、YouTube | 描述目标，自动规划执行，交付桌面结果；强 before/after 耗时对比 | Reddit research、sales analysis、blog visuals、file/data/docs automation | 用中文资料和本土平台做同题挑战：小红书、公众号、飞书表格、中文 PDF |
| WorkBuddy | Tencent Cloud、Techpedia、腾讯官方新闻、LinkedIn、X、YouTube 评论/评测 | 一条 brief + 100+ experts + 并行 agents，像 AI 员工一样处理一整天办公任务 | AI employee、entire workday、remote control、ready-to-use deliverable | 不喊“替代员工”，主打“中文复杂工作交付台 + 可验证结果” |

## 3. 单个竞品拆解

### 3.1 Claude / Claude Cowork

| 维度 | 观察 |
|---|---|
| 社媒主阵地 | 官网产品页 `claude.com/product/cowork`，Learn / Academy，Help Center，Claude / Anthropic LinkedIn，YouTube，X。国内平台主要是搬运和教程型二创，B站可补采“Claude 101 / AI Fluency / Claude Code 官方课程”关键词。 |
| 内容栏目 | AI Fluency、Claude 101、Claude for Work、Claude for Small Business、Cowork task loop、plugins / skills / connectors、行业解决方案、客户案例、Help Center 教程。 |
| 标题风格 | 教育型、课程型、职业能力型。典型模式是 “Getting started with X”“Claude for work”“AI Fluency”“Introduction to Cowork”“How to build a plugin”。标题不炫技，强调“学会”和“落地”。 |
| 视觉 / 表达风格 | 官网端是高信任、克制、企业化；课程端像学院；社媒端常用产品界面、工作流图、真实角色/团队语境，不靠夸张效率数字。 |
| CTA | Try Claude、Download、Request demo、View course、Learn more、Browse plugins、Contact sales。 |
| GTM 节奏 | 先教育用户“会用 AI 是工作能力”，再用 Cowork / plugins / connectors 把能力落到团队、文件、工具和行业任务。新品发布后迅速配 Help Center、课程、插件市场和行业案例。 |
| Kimi 适合学什么 | 学“教育体系 + 任务交付”的组合：Kimi Work 101、Agent Fluency、岗位课、任务包、插件/模板式复用。每条内容都要教用户怎样委派、补资料、校验、迭代。 |
| Kimi 不该学什么 | 不要照搬过强学院感。中国泛职场用户更需要“给我一个能直接交差的模板/流程/示例”，不只是一门课。 |

Kimi 反制选题：

1. `Kimi Work 101：第一次别问问题，直接交给它一个真实任务`
2. `会用 Kimi 的 4 个动作：委派、补资料、让它自查、改成可交付物`
3. `把 20 个网页交给 Kimi，做一版竞品观察周报`
4. `Kimi 做完后，我会让它自查这 5 个风险`
5. `小团队怎么用 Kimi 跑一次从客户反馈到营销素材的闭环`

### 3.2 OpenAI Codex

| 维度 | 观察 |
|---|---|
| 社媒主阵地 | OpenAI 官网、OpenAI Academy、Developers use cases、OpenAI / OpenAI Developers YouTube、X、LinkedIn、Forum。 |
| 内容栏目 | Codex for everyday work、Codex for every role/tool/workflow、productivity and collaboration、role-specific plugins、Sites、annotations、best practices、use case collections。 |
| 标题风格 | 结果型、角色型、workflow 型。典型模式是 “How to use Codex for everyday work”“Codex for every role, tool, and workflow”“Create a daily brief”“Research to decision memo”。 |
| 视觉 / 表达风格 | OpenAI 风格偏简洁、产品截图少而抽象；Academy 内容更像教程目录，用任务清单降低门槛。它正在主动淡化“只给程序员用”的印象。 |
| CTA | Download Codex、Watch webinar、Try example prompts、Read report、Explore use cases、Install plugins。 |
| GTM 节奏 | 先用 coding agent 建立高能力心智，再通过 Academy 和 use cases 把非开发者纳入：brief、summary、deck、workbook、plan、process doc、finance review、campaign kit。 |
| Kimi 适合学什么 | 学“非代码用户的任务枚举”和“review-ready output”表达。Kimi 要把报告、表格、PPT、研究、运营、销售、管理这些结果放到标题前半句。 |
| Kimi 不该学什么 | 不要把“能写代码/能建站”作为主卖点。Kimi 要把代码能力隐藏在交付物背后，让非代码用户感觉自己是在推进业务，不是在学开发。 |

Kimi 反制选题：

1. `非程序员也能用 Kimi 做 agent：市场人一下午交付 campaign kit`
2. `从老板一句话到决策 memo：Kimi 怎么拆任务`
3. `把 6 个表格给 Kimi，它做出一份月度经营复盘`
4. `不是写代码：用 Kimi 搭一个可分享的项目资料页`
5. `Kimi 同题挑战：把用户反馈变成产品改进清单`

### 3.3 Trae Work

| 维度 | 观察 |
|---|---|
| 社媒主阵地 | TRAE 官网、LinkedIn、YouTube、Reddit、B站教程/官方教程线索。 |
| 内容栏目 | Work Mode、Design Mode、Code Mode、SOLO、AI IDE 教程、real-world builds、spec-driven development、UI / prototype / build demos。 |
| 标题风格 | 构建型、闭环型、发布型。典型模式是 “Introducing Design Mode in TRAE Work”“Work Mode -> Design Mode -> Code Mode”“Let TRAE work for you”“Ship faster”。 |
| 视觉 / 表达风格 | 更产品工程化，强调流程闭环、原型、代码、界面预览和设计系统。LinkedIn 适合讲专业工作流，YouTube/B站更适合演示。 |
| CTA | Download、Try TRAE、Join community、Watch tutorial、Build with TRAE。 |
| GTM 节奏 | 从 AI IDE / SOLO 的开发者心智，扩到 PM、founder、designer：先计划，再可视化，再构建。Design Mode 是补齐“想法到可见稿”的关键扩张。 |
| Kimi 适合学什么 | 学“多阶段流程命名”：Kimi 也要把复杂工作拆成资料 -> 结构 -> 交付 -> 复盘，而不是泛泛说“帮你分析”。 |
| Kimi 不该学什么 | 不要和 Trae 正面争“从需求到代码”。Kimi 应避开纯构建战场，抓住产品经理、运营、市场、销售在构建前后的资料处理、方案生成、复盘管理。 |

Kimi 反制选题：

1. `Kimi 的工作流不是 Work/Design/Code，而是资料/结构/交付/复盘`
2. `产品经理写 PRD 前，先让 Kimi 做市场和竞品证据`
3. `运营活动从复盘到下次方案，Kimi 一次跑完`
4. `哪些非开发任务最适合 Kimi：研究、内容、求职、学习、投研`
5. `碎片想法变可执行计划，不一定要进入代码`

## 5. 非代码知识工作者内容机会

Kimi 的机会不是泛泛说“人人都能用”，而是把非代码用户的真实交付物讲清楚。

| 场景 | 用户痛点 | Kimi 内容机会 | 标准输入 | 标准输出 | CTA |
|---|---|---|---|---|---|
| 报告 | 资料多、结构乱、老板要结论 | `从 20 个网页到一份行业观察报告` | 网页、PDF、会议记录、旧报告 | 摘要、证据表、机会点、风险、建议 | 领取报告结构模板 |
| 表格 | 表格散、字段不统一、不会透视 | `不会 Excel 公式，也能做月度经营复盘` | 多张 Excel / CSV、字段说明 | 清洗口径、指标表、图表建议、洞察 | 复制表格分析任务描述 |
| PPT | 不会从资料变成可讲故事的页 | `资料太多，先让 Kimi 出 PPT 大纲` | 资料包、目标听众、页数 | 章节、每页标题、关键证据、视觉 brief | 领取 PPT 大纲模板 |
| 研究 | 搜索结果多，证据难归类 | `Kimi 帮你做一张研究证据地图` | 论文、新闻、官网、访谈 | 主题聚类、分歧、来源、待验证问题 | 用你的主题试一次 |
| 合同 | 看不懂风险，但又不能让 AI 代替律师 | `合同初筛：Kimi 只做问题清单，不做法律结论` | 合同文本、交易背景、关注点 | 条款摘要、风险问题、需律师确认项 | 下载合同审阅问题清单 |
| 运营 | 活动复盘总是流水账 | `把活动数据和用户反馈变成下次行动方案` | 活动数据、评论、投放记录 | 指标变化、问题归因、下次动作、owner | 领取活动复盘模板 |
| 销售 | 拜访前资料收集耗时 | `客户拜访前 30 分钟，用 Kimi 做拜访包` | 客户官网、新闻、CRM 备注、产品资料 | 客户背景、痛点假设、问题清单、跟进话术 | 复制销售拜访任务包 |
| 团队管理 | 会议后没有动作闭环 | `会议结束 10 分钟，Kimi 生成行动清单和风险表` | 会议纪要、项目目标、成员职责 | action item、owner、deadline、risk、下次议题 | 领取会议行动清单模板 |

内容优先级：

1. 先做“报告、表格、PPT、研究”四个高频可视化场景，用截图/样张建立信任。
2. 再做“合同、销售、团队管理”三个高价值场景，但明确人审边界。
3. 每个场景都要有“原始输入 -> Kimi 过程 -> 可交付输出 -> 校验方式 -> 模板 CTA”。

## 6. 6 周竞品响应机制

### 6.1 每周看什么

| 周期 | 观察重点 | 必看来源 | 记录标准 |
|---|---|---|---|
| 每周一 | 官网 / Academy / docs 是否新增页面、课程、插件、用例 | Claude product / Learn / Help，OpenAI Academy / Codex use cases，Trae blog/docs，Qoder docs，Tencent Cloud / Techpedia | 新页面 URL、标题、目标人群、CTA、是否官方 |
| 每周二 | YouTube / X / LinkedIn / B站 / 公众号公开标题 | 官方账号、搜索结果、搬运号、媒体号 | 只记录可验证标题，不写无法打开的具体数据 |
| 每周三 | 把竞品动作转成 Kimi 候选选题 | 本周新增内容 + 历史标题模式 | 每个竞品至少 2 条 Kimi 反制选题 |
| 每周四 | 产出 2 条深度拆解或同题挑战 | 选择最强竞品动作 | 脚本、素材 brief、截图清单、模板 CTA |
| 每周五 | 更新 tracker 和周报 | `templates/competitor-tracker.csv` 同结构表 | 状态从 `new` 到 `turned_into_topic` 或 `archived` |

### 6.3 从竞品内容转成 Kimi 选题

固定四步：

1. 识别竞品承诺：它到底承诺了什么结果？例如报告、PPT、Excel、网站、合同审阅、销售线索。
2. 找 Kimi 优势场景：中文资料、国内平台、长文本、多文件、可修改文档、团队交付、成本更低。
3. 改写标题：不要照抄竞品标题，把“竞品功能词”改成“Kimi 用户任务词”。
4. 绑定 CTA：评论领取模板、打开 Kimi 试同款、下载任务包、加入每周同题挑战。

## 7. Kimi 官方账号 10 条打法建议

1. 固定做 `Kimi Work 101`：每周 3 条，只讲一个真实任务、一个输入材料、一个可交付结果。
2. 固定做 `Agent Fluency`：每周 2 条，教委派、补上下文、校验、迭代，不讲空泛 prompt 技巧。
3. 做 `从资料到交付物` 系列：每条展示原始资料截图、Kimi 处理过程、最终报告/表格/PPT 样张。
4. 做 `某岗位怎么用 Kimi`：产品、运营、市场、销售、研究、法务、管理者、学生，各有任务包。
5. 做 `竞品同题挑战`：不攻击竞品，用同一个任务证明 Kimi 在中文资料和本土工作流里的优势。
6. 做 `模板库 CTA`：每条内容都沉淀到一个可领取模板，不让流量只停留在观看。
7. 做 `高压交付急救包`：老板临时要方案、周五要复盘、客户明早拜访、投研材料太长。
8. 做 `结果验收清单`：教用户判断 AI 输出是否能交差，强化 Kimi 的可靠和专业感。
9. 做 `团队试点场景`：周报、竞品、销售拜访、运营复盘这 4 个最适合转团队付费。
10. 做 `每周竞品雷达`：官方账号可以低频发布“本周 AI 工作台新趋势”，把 Kimi 放在行业观察者位置。

## 8. 达人投放 10 条打法建议

1. 不给达人泛 prompt，给“任务包”：资料、目标、Kimi 操作步骤、结果样张、口播重点。
2. 按达人类型分发任务：职场效率讲周报/会议，产品运营讲竞品/复盘，销售讲拜访包，学习达人讲资料整理。
3. 让达人展示自己的真实资料，但必须做隐私脱敏，避免演示看起来像假 demo。
4. 每条达人内容必须有 before/after：原始资料多乱，Kimi 输出多清楚。
5. 把“省时间”作为钩子，把“能交差”作为结论，避免只停留在效率爽点。
6. 达人标题使用任务语言：`老板临时要方案，我用 Kimi 先交一版`，少用功能名。
7. 每周安排 1 条同题挑战：不同达人用 Kimi 处理同一类资料，形成栏目感。
8. 给达人配套评论区转化：模板领取、任务描述复制、官方账号合集、Kimi 入口。
9. 投放时优先小红书、B站、抖音、公众号/视频号的职场与知识工作达人，而不是只投 AI 工具评测号。
10. 建达人复盘表：记录标题、任务、受众、内容格式、模板领取、评论问题，再反哺官方选题。

## 10. 最重要的 5 个建议

1. Kimi 的主心智应定为“中文复杂知识工作交付台”，不要跟竞品一起卷纯 coding agent。
2. 立刻建立 `Kimi Work 101 + Agent Fluency + 从资料到交付物` 三个常设栏目，用教育降低委派门槛，用交付物建立信任。
3. 把非代码知识工作者作为社媒突破口：报告、表格、PPT、研究、合同、运营、销售、团队管理，每个场景都配任务包。
4. 所有内容都要从“原始输入”讲到“最终输出”和“校验方法”，只讲功能会输给 Claude / Codex 的教育体系，也输给 Qoder / WorkBuddy 的效率叙事。
5. 建 6 周竞品响应机制：每周看官方/社媒/中文平台，转成 Kimi 选题，进 tracker，做同题挑战，最后用模板领取和试用数据决定栏目去留。
