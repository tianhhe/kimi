# Kimi 高付费受众分层 V2

更新日期：2026-07-02

## 1. 为什么重拆

原先的人群拆分偏“岗位名”，不够支撑增长运营。参考 Claude Solutions 的拆法，Kimi 需要同时按六个维度看受众：

1. 公司规模：个人、自由职业者、小团队、初创公司、SMB、企业部门、受监管组织。
2. 部门/职能：产品、运营、市场、销售、CS、研究、咨询、财务、法务、HR、教育、内容、研发、管理者。
3. 行业：金融、医疗/生命科学、教育、法律、政府/公共部门、非营利、软件/AI、电商/本地服务、内容/媒体。
4. 任务类型：研究、写作、表格分析、PPT、资料整理、流程自动化、客户沟通、合规审查、代码/产品构建。
5. 付费触发：省时间、减少返工、带来收入、降低风险、团队复用、紧急节点、数据复杂度高。
6. 采用成熟度：AI 好奇者、模板用户、工作流用户、Agent 委派者、团队推广者、采购/管理员。

增长运营的核心判断不是“这个人会不会用 AI”，而是“这个人有没有一类反复发生、成本很高、结果可验证、愿意为效率和质量付费的任务”。

## 2. P0 人群

P0 是社媒内容、达人投放和功能 GTM 的优先人群。他们的特点是时间贵、任务复杂、结果可验证、愿意为减少返工或提升产出付费。

| 人群 | 典型角色 | 高价值任务 | Kimi 主卖点 | 首个内容钩子 | 首个模板/资产 |
|---|---|---|---|---|---|
| 小团队老板/创始人 | 创始人、独立开发者、工作室负责人 | 投资人 update、经营周报、客户跟进、招聘 JD、增长计划 | 一个人补齐研究、运营、销售、文档能力 | `一个人公司如何用 Kimi 搭小型增长团队` | 小团队经营周报包 |
| 产品/PMM/增长负责人 | PM、PMM、增长、GTM | 竞品分析、路线图证据、功能发布、用户反馈聚类 | 从资料到决策材料 | `把 30 条用户反馈变成路线图证据` | 产品证据表 + GTM brief |
| 销售/BD/CS 管理者 | 销售经理、BD、客户成功 | 客户研究、拜访提纲、异议处理、续费复盘、案例包装 | 把分散客户信息变成行动包 | `会前 15 分钟生成客户风险表` | 客户拜访与续费包 |
| 咨询/投研/战略 | 咨询顾问、投研、VC、战略分析 | 行业研究、公司对比、访谈提纲、memo、deck | 长资料阅读与结构化交付 | `见客户前做一份行业预诊断` | 行业预诊断模板 |
| 内容/品牌/代理商 | 内容团队、品牌、营销代理商、MCN | 选题、脚本、素材审计、campaign、客户 brief | 素材库到内容资产 | `把一堆素材变成 30 天栏目` | 栏目选题和脚本包 |
| 财务/法务/HR/运营支持 | 财务 BP、法务、HRBP、行政运营 | 合同摘要、政策 FAQ、预算复盘、入职计划、流程 SOP | 高风险材料的结构化和校验 | `把制度文档变成员工能懂的 FAQ` | 内部运营 SOP 包 |
| 受监管行业专业人群 | 金融、医疗、法律、生命科学、安全 | 尽调、合规、病历/文献摘要、研究记录、风险审查 | 可追溯、可复核、可人审 | `高风险任务为什么更需要验收清单` | 合规验收清单 |
| 团队推广者/管理员 | 企业 AI champion、部门负责人、数字化负责人 | 团队模板库、权限规范、采用培训、ROI 复盘 | 让团队形成可管理的 AI 工作流 | `一周让团队 5 个人各完成一个 Kimi 任务` | 团队采用打卡表 |

## 3. P1 人群

P1 适合做规模增长、模板传播、达人共创和社群任务，但需要用具体节点提高付费意愿。

| 人群 | 付费/转化触发 | 内容策略 | Kimi 资产 |
|---|---|---|---|
| 研究生/科研助理 | 论文、开题、文献综述、实验/访谈资料 | 不讲泛学习，讲“材料到论文框架/答辩材料” | 文献综述包、开题报告包 |
| 求职/转岗人群 | 简历、面试、作品集、行业认知 | 用节点压力转化，适合小红书/知乎/B站 | JD 解析、定制简历、面试题库 |
| 创作者/自媒体 | 选题枯竭、脚本、账号复盘、矩阵分发 | 强演示和模板传播，适合达人投放 | 选题库、脚本库、账号复盘表 |
| 教师/培训师/教育工作者 | 课程设计、作业反馈、学习路径 | 对标 Claude education，强调负责任使用 | 课程设计包、学生 AI 使用规范 |
| 自由职业者/服务商 | 报价、提案、客户研究、交付复盘 | 付费意愿取决于能否帮助成交或交付 | 报价依据表、提案前调研包 |
| 开发者/数据/自动化用户 | 工具链、脚本、数据处理、agent 编排 | 可引导到 Kimi Agent/多 agent 高阶教程 | Agent 工作流包、数据分析模板 |

## 4. P2 人群

P2 可以贡献规模和品牌认知，但不应消耗太多高成本内容资源。

| 人群 | 风险 | 适合内容 | 不适合动作 |
|---|---|---|---|
| 泛办公白领 | 任务碎、付费弱，容易只收藏不使用 | 低门槛模板、周报/会议纪要/邮件 | 不宜主打高价功能 |
| 普通学生 | 规模大但预算低，容易停留在问答 | 学习计划、考试整理、资料总结 | 不宜过早做付费转化 |
| 个人生活用户 | 传播性强但业务价值弱 | 旅行、购物、生活规划的轻内容 | 不作为主预算投放人群 |
| AI 尝鲜用户 | 来得快走得快，容易追热点 | 新功能体验、对比实验 | 不作为核心留存指标 |

## 5. 受众优先级评分

每个候选人群用 100 分打分：

| 维度 | 权重 | 判断方式 |
|---|---:|---|
| 任务复杂度 | 20 | 是否需要多材料、多步骤、多轮校验 |
| 结果价值 | 20 | 输出是否影响收入、效率、决策或风险 |
| 复用频率 | 15 | 是否每周/月重复发生 |
| Kimi 差异化 | 15 | 是否能体现长材料、Agent、Work、模板库优势 |
| 社媒可展示性 | 10 | 是否能用输入-过程-输出清晰演示 |
| 付费/线索意图 | 15 | 是否会问团队、权限、价格、模板、服务 |
| 达人可扩散性 | 5 | 是否有垂类达人能真实演示 |

P0 标准：80 分以上。P1 标准：65-79 分。P2 标准：64 分以下或付费路径不明确。

## 6. 按 Claude Solutions 补全的 Kimi 人群入口

| Claude 入口 | Kimi 入口 | Kimi 不应照搬的点 | Kimi 应强化的点 |
|---|---|---|---|
| AI agents | Kimi Agent / Agent Swarm | 不要只讲自动化炫技 | 任务判断、分工、过程可控、结果验收 |
| Coding / Code modernization | Kimi for 产品构建 / 数据自动化 | 不要和专业 coding agent 正面硬卷 | 强调非代码人群也能完成页面、脚本、分析、自动化雏形 |
| Startups | Kimi for 小团队/创始人 | 不要只做创业鸡血 | 周报、销售、招聘、投研、运营的一人多岗 |
| Enterprise | Kimi for 团队 | 不要只说提效 | 权限、模板库、培训、ROI、管理员视角 |
| Legal / Security | Kimi for 法务/安全/合规 | 不要承诺替代专业判断 | 人审、引用、风险清单、审批流 |
| Financial services | Kimi for 投研/财务/金融分析 | 不要泛泛讲理财 | 尽调、财报、memo、模型校验、合规边界 |
| Healthcare / Life sciences | Kimi for 医疗科研/生命科学资料 | 不要做诊断承诺 | 文献、研究、合规、可追溯分析 |
| Education / Nonprofits | Kimi for 教育/公益 | 不要只打低价 | 课程、学习路径、项目报告、筹款材料 |
| Customer support | Kimi for 客服/CS | 不要只做机器人问答 | FAQ、工单聚类、续费风险、客户案例 |

| 产品/增长/PMM 博主 | 产品、GTM、增长 | 竞品分析、路线图、功能发布 |

## 10. 运营动作

1. 月度内容排期先选 3 个 P0 人群、2 个 P1 人群，不同时覆盖太多。
2. 每个人群至少做 10 条短内容、2 条长教程、1 个模板包、1 场直播/社群任务。
3. 每周复盘时按人群看收藏率、模板领取、首个高价值任务、D7 复用、付费/线索。
4. 若某人群收藏高但任务完成低，说明需要降低首用门槛；若私信多但功能激活低，说明需要更强 onboarding；若任务完成高但付费低，说明要引入团队/复用/权限价值。
5. 每月把最强人群升级成官网 solution 页和案例库，而不是只继续发内容。
