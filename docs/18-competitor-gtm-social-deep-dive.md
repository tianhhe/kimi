# 竞品功能-GTM-社媒内容打法深挖

更新日期：2026-07-02

本文件继续补强 `docs/09-competitor-deep-dive.md` 和 `docs/10-social-channel-title-swipe.md`，重点看 Claude/Cowork、OpenAI Codex、Trae Work、Qoder Work、WorkBuddy 如何把功能包装成 GTM 主张、官网教育、社媒栏目和转化路径。核心问题不是“谁功能更多”，而是谁能把用户从“我试试 AI”带到“我愿意把真实工作交给它”。

## 0. 一句话结论

Kimi 不应该把自己讲成另一个通用聊天助手，也不应该被拖进纯 coding agent 战场。更好的位置是：中文复杂工作交付系统。也就是把真实资料、网页、文件夹、表格、会议记录、业务目标交给 Kimi，最终拿到可保存、可修改、可复用的文档、表格、PPT、网页、周报、方案和复盘。

## 1. 横向比较：竞品到底在卖什么

| 维度 | 最强竞品 | 他们在卖的不是 | 他们实际在卖 | Kimi 的响应方向 |
|---|---|---|---|---|
| 谁在教育用户 | Claude / Cowork | 单个模型能力 | AI Fluency、Claude 101、Claude for Work、task loop、可验证协作习惯 | 做 `Kimi Work 101` 和 `Agent Fluency`，教用户委派、描述、校验、迭代 |
| 谁在卖自动化 | Qoder Work / WorkBuddy | 聊天回答 | 自然语言 -> 规划 -> 执行 -> 交付，省掉重复办公步骤 | 强化“从文件夹到交付物”，每条内容都展示输入、过程、输出 |
| 谁在卖 AI 员工 | WorkBuddy | 工具集合 | 100+ 专家、并行协作、IM 远程控制、业务流程包 | 学角色包和流程包，但避免“万能员工”造成期待过高 |
| 谁在卖 coding agent | Codex / Trae IDE / Qoder coding suite | 代码补全 | 端到端任务代理、读上下文、改文件、跑验证、交付结果 | 不和开发心智硬碰，强调非代码知识工作也能被 agent 化 |
| 谁在卖工作成果 | Codex / Claude Cowork / Qoder Work | prompt 技巧 | 报告、表格、PPT、合同、仪表盘、设计稿、研究摘要、决策 memo | Kimi 每个内容单元都以“最终产物”收口 |

关键判断：

1. Claude 的壁垒是教育系统。它让用户相信“会用 AI 是工作能力”，再用 Cowork 把能力落到真实文件和任务。
2. Codex 的增长机会已经不止开发者。OpenAI 官方明确把 Codex 扩到报告、表格、演示、合同、研究、数据分析、营销活动包等知识工作。
3. Trae Work 把 coding agent 扩成 Work/Design/Code 的产品生产线，强项是从想法到可运行产品。
4. Qoder Work 的强项是“交付物 + 耗时对比”，最适合短视频和案例页传播。
5. WorkBuddy 的强项是企业采购语言：一人等于一队专家、IM 远程控制、办公室全场景。
6. Kimi 的机会不在“我也有 agent”，而在“中文资料密集场景下，我能交付更像中国职场真正要用的结果”。

## 2. Claude / Claude Cowork

### 产品定位

Claude 主产品卖“可信 AI 协作者”，Claude Cowork 则把 Claude 从聊天窗口推进到桌面和本地文件。这里要把两个站分开看：`anthropic.com` 更像公司叙事、研究、信任和教育中心；`claude.com` 才是 Claude 产品站和转化漏斗，围绕 product、solutions、connectors/plugins、customers、courses、pricing、contact sales 把用户从 SEO 入口一路带到试用、下载、付费和销售线索。Anthropic 官网对 Cowork 的定位非常清楚：给它一个目标，它会在电脑、本地文件和应用之间工作，返回完成的 deliverable。这个定位天然服务非技术知识工作者，而不是只服务开发者。

### 核心功能

| 功能层 | 具体能力 | 对 GTM 的意义 |
|---|---|---|
| Claude 基础 | 聊天、写作、研究、总结、分析 | 宽入口，适合教育新用户 |
| Artifacts | 创建、管理、协作文件和内容 | 把回答变成可见产物 |
| Projects | 组织复杂任务和上下文 | 让用户相信 Claude 能长期参与一项工作 |
| Skills | 用结构化指令和资源完成特定任务 | 把“会用 Claude”产品化成可复用流程 |
| Connectors / Tools | 连接 Google Docs、GitHub、分析工具等 | 从聊天进入工作栈 |
| Claude Cowork | 本地文件、文件夹、应用、多步任务、研究综合、文档准备、数据抽取 | 把“问答”升级成“代办工作” |

### 目标人群

Claude/Cowork 的人群是“有判断力但缺时间的人”：研究员、分析师、运营、法务、财务、市场、非营利组织、小企业主、教育工作者。它不是先问“你懂不懂 prompt”，而是先问“你有没有重复、费时、但又需要判断的工作”。

### GTM 主张

Claude 的 GTM 由两层组成：

| 层级 | 内容资产 | 主张 |
|---|---|---|
| 教育层 | AI Fluency、Claude 101、Claude for Work、Claude for personal、Academy course | 会用 AI 是一种职业能力 |
| 执行层 | Claude Cowork、Small Business workflows、Skills、Connectors | Claude 不只回答，而是和你一起完成真实工作 |

AI Fluency 的关键不是“prompt 教程”，而是 4D 框架：Delegation、Description、Discernment、Diligence。它把用户教育成更好的委派者、描述者、校验者和迭代者。Claude Cowork 接住这个教育结果，把 task loop 做成产品：目标 -> 本地文件/工具 -> 计划 -> 执行 -> 结构化结果 -> 人类校验。

### 官网内容组织

Claude 官网把“模型能力”放在产品线里，但真正转化靠 Learn 和 Solutions：

1. Learn：Claude for personal、Claude for work、AI Fluency、Claude 101、课程证书。
2. Product：Claude、Claude Code、Claude Cowork、Claude Design、Claude Science、安全和企业能力。
3. Use cases：Engineering、HR、Marketing、Product、Sales、Education、Small business。
4. Cowork 页面：先讲为什么聊天不够，再讲非技术任务、本地文件、多来源综合、最终 deliverable。
5. Small Business 页面：直接把 QuickBooks、PayPal、HubSpot、Canva、Docusign 等业务工具串成 payroll、month close、sales campaign、invoice chasing 等 workflow。

### Claude.com 产品站 GTM / SEO / 转化结构

`claude.com` 的产品站不是简单导航页，而是一套从“问题意识”到“采购动作”的 SEO 和转化系统。它把 Claude 拆成 5 类搜索入口：产品词、任务词、行业词、角色/插件词、采购词。

| Claude.com 模块 | SEO 捕获词 | 页面 GTM 主张 | 转化动作 | 对 Kimi Agent / Kimi Work 的映射 |
|---|---|---|---|---|
| `/product/overview` | AI for problem solvers、Claude overview、AI assistant for work | `The AI for problem solvers`，从 break down problems、toughest work、tasks/learn/code/research/analyze/create 切入 | Ask Claude、下载桌面端、移动端试用、Explore Cowork | Kimi Work 首页应从“中文复杂工作交付系统”切入，展示任务分类：写作、学习、研究、分析、表格、PPT、网页、自动化 |
| `/product/claude-code` | AI coding agent、Claude Code、terminal IDE Slack | 读 codebase、改文件、跑命令，终端/IDE/桌面/web/Slack 多入口 | Download、Developer docs、Try Claude Code、Team/Enterprise seat | Kimi Agent 不要被纯代码心智绑定，但要学习“在用户原有工具里工作”：浏览器、文件夹、表格、网页生成、自动化脚本 |
| `/product/cowork` | AI for knowledge work、desktop AI agent、Claude Cowork | `Delegate to Claude, delight in the result`；Schedule tasks、Organize files、Build spreadsheets、Prepare reports、Analyze notes | Download Claude、Talk to sales、Pair your phone、Enterprise admin controls | Kimi Work 应做独立任务代理页：从本地/云端资料到周报、表格、PPT、研究 memo；强调“交代结果和节奏，回来收成果” |
| `/solutions/*` | Claude for legal、financial services、healthcare、education、small business、enterprise | 每个行业页都把 Claude 放进已有工作流：法律 redline、金融 signal to decision、医疗 ecosystem、小企业 day-one workflows | Contact sales、Try Claude、行业资源、webinar、product guide | Kimi 需要行业/岗位页：运营、市场、产品、销售、咨询、投研、学习、求职。每页必须有场景、输入材料、输出资产、模板 CTA |
| Connectors / Plugins | Claude connectors、Claude plugins、Sales plugin、MCP | 插件把 skills、connectors、sub-agents 打包成角色/团队可用的 ready-to-go setup | paid plans、install plugin、connect CRM/email/docs、private marketplace | Kimi 不只做模板库，还要做“任务包/技能包”：竞品监控包、周报包、销售拜访包、活动复盘包、内容选题包 |
| `/customers` | Claude customers、Claude case studies、industry proof | 可按行业、产品、公司规模、地区、partner 过滤；用 Notion、Slack、Figma、HubSpot 等客户证明实际价值 | Read story、Contact sales、Try Claude | Kimi 需要案例库，不只达人内容。每个案例按“输入 -> Kimi 执行 -> 输出 -> 节省/质量提升 -> 可复用模板”写 |
| `/resources/courses` | Claude courses、AI Fluency、Claude 101、Cowork course | structured learning paths，按产品和类别过滤，覆盖 AI Fluency、Claude.ai、Claude Code、Claude Cowork、Platform、MCP | View course、Academy、Try Claude | Kimi 需要 `Kimi Academy`：Kimi Work 101、Agent Fluency、岗位课、模板课、案例复盘课 |
| `/pricing` | Claude pricing、Team plan、Enterprise plan | 先用问答式 plan recommender 匹配安全、用量、合同需求，再展示 Free/Pro/Max/Team/Enterprise | Try Claude、Get Team plan、Get Enterprise、Contact sales | Kimi 的定价/转化页要按个人高频、团队协作、企业安全分层，避免只列价格；要解释哪些功能支撑高价值工作 |
| `/contact-sales` | Claude contact sales、enterprise deployment | 区分快速自助和复杂销售：知道需求就自助买 Enterprise，有问题找 buying agent，500+ seats/BAA 才进销售 | Get Enterprise、Chat with buying agent、Support center、Contact sales | Kimi 可以设计“先自助开始，再销售介入”的路径：个人模板包 -> 团队任务包 -> 企业安全/部署咨询 |

这套产品站结构的核心不是“页面多”，而是每个页面都承担一个漏斗职责：

1. `product/overview` 负责建立总心智：Claude 是 problem solver，不只是 chat。
2. `product/cowork` 负责把非代码知识工作转成可委派任务：schedule、organize、build、prepare、analyze。
3. `product/claude-code` 负责保留开发者高价值入口，并证明 agent 可以在真实工具栈里工作。
4. `solutions/*` 负责吃行业 SEO 和企业预算，每个行业都用“已有工具 + 关键任务 + 安全/合规 + 资源”组织。
5. `plugins/connectors` 负责把泛 agent 变成部门 agent、岗位 agent 和企业私有 marketplace。
6. `customers` 负责 proof，不讲抽象能力，而讲真实公司和真实工作。
7. `courses/resources` 负责教育，让用户知道怎样把 Claude 用深。
8. `pricing/contact-sales` 负责分流：个人试用、团队自助、企业销售。

### Kimi Agent / Kimi Work 对应页面结构建议

| Kimi 页面 | 对标 Claude.com | 页面主张 | 内容模块 |
|---|---|---|---|
| Kimi Work overview | `product/overview` | 中文复杂工作，从资料到交付物 | 任务分类、真实输入、输出资产、桌面/网页/移动入口、模板 CTA |
| Kimi Agent / Work delegation | `product/cowork` | 把一件真实工作交给 Kimi，回来拿可用结果 | 资料夹整理、网页研究、表格汇总、PPT/报告、定时周报、多 agent 分工 |
| Kimi for creators / marketers / operators | `solutions/*` | 某岗位怎么用 Kimi 完成高频交付 | 岗位痛点、工作流、示例输入、示例输出、可复制任务描述 |
| Kimi task packs | `plugins/sales` 和 plugins docs | 开箱即用的任务包，而不是空白 prompt | 竞品监控包、销售拜访包、活动复盘包、内容选题包、求职包、学习包 |
| Kimi customers / creator cases | `/customers` | 谁用 Kimi 解决了什么真实问题 | 按行业/角色过滤，展示前后对比和可复用模板 |
| Kimi Academy | `/resources/courses` | 会用 Kimi 是一种工作能力 | Kimi Work 101、Agent Fluency、岗位课、模板课、复盘课 |
| Kimi pricing / contact | `/pricing` 和 `/contact-sales` | 按任务价值而不是 token 售卖 | 个人、团队、企业分层；安全、用量、协作、模板/任务包权益 |

对 Kimi 最有价值的借鉴是：Claude.com 把“产品能力”拆成了用户会搜索、销售会转化、内容能持续更新的页面体系。Kimi 也应该从单个功能页升级为一套 GTM 站点结构，核心 SEO 词可以围绕 `中文 AI agent`、`AI 工作台`、`AI 周报`、`AI 竞品分析`、`AI PPT`、`AI 表格分析`、`AI 资料整理`、`Kimi Work 101`、`Kimi Agent`、`Kimi 任务包` 来铺。

### 社媒栏目 / 标题风格

本地标题采样里，Claude 系最典型的标题是：

| 栏目 | 标题风格 | 意图 |
|---|---|---|
| Getting started | `Getting started with Claude.ai`、`Claude AI 101` | 降低首用门槛 |
| Prompting / Fluency | `Prompting 101`、`AI Fluency: Framework & Foundations` | 把使用方法变成课程 |
| Mastering | `Mastering Claude Code` | 服务高阶用户 |
| Claude for X | Claude for Work、Small Business、Education、Nonprofits | 用行业和角色包装采购理由 |
| Cowork task loop | 本地文件、研究综合、文档准备、数据抽取 | 展示“从目标到交付物” |

标题不是炫技，而是“你如何成为更会用 AI 的人”。这点很值得 Kimi 学。

### 转化路径

Claude 的路径是：教育内容 -> 课程/用例 -> 真实 task loop -> 免费或付费试用 -> Team/Enterprise/Small Business -> connectors/skills 深度绑定。Cowork 的页面还有一个明确设计：先指出聊天窗口不足，再把非技术知识工作者的多步工作包装成 Cowork 的自然入口。

### Kimi 可学 / 应避 / 可反击

| 类型 | 结论 |
|---|---|
| 可学 | 建 `Kimi Work 101`、`Agent Fluency`、`某岗位怎么用 Kimi`，用教育体系降低复杂工作委派门槛 |
| 可学 | 每个功能都绑定第一个真实任务：周报、竞品分析、活动复盘、资料夹汇总、会议行动清单 |
| 可学 | 用“委派-描述-校验-迭代”训练用户，而不是只教 prompt |
| 应避 | 不要只学 Claude 的学院感。中国用户更需要“直接给我一个能交差的模板” |
| 应避 | 不要把 polished output 当完成。Kimi 内容必须教用户怎么验真、补证据、改口径 |
| 可反击 | Claude 强在英语和企业教育，Kimi 可主打中文资料、中文平台、小红书/知乎/公众号/B 站、中文职场文档 |

## 3. OpenAI Codex：非代码知识工作者机会

### 产品定位

Codex 原本是 coding agent，但 OpenAI 的新叙事已经从“帮开发者写代码”扩展成“让每个角色把工作交给 agent”。OpenAI 官方明确说 Codex 不再只是 coding tool，知识工作者主要用它创建报告、表格、演示、合同等 work products，也用它做研究、数据分析、流程自动化和轻量工具。

这对 Kimi 很关键：Codex 正在把 coding agent 的方法论迁移到知识工作，Kimi 必须提前占住“非代码知识工作 agent”心智。

### 核心功能

| 功能层 | 官方表达 | 对非代码用户的意义 |
|---|---|---|
| Codex agent | 读上下文、改文件、执行任务、验证结果 | 把“我要做什么”变成“让 agent 推进” |
| Plugins | 适配角色、工具、工作流 | 分析师、市场、设计、投资、运营都有入口 |
| Sites | 把工作变成可分享的网站或应用 | 结果不只存在聊天里，可以被团队查看 |
| Annotations | 就地标注和修改结果 | 让用户从“让 AI 做”进入“审阅和迭代” |
| Use cases | Inbox、computer use、feedback to action、messy data、productivity collaboration | 非代码任务被明确纳入 Codex 场景 |

### 目标人群

OpenAI 官方提到非开发用户包括 analysts、marketers、operators、designers、researchers、investors、bankers。它的非代码人群不是泛泛的办公人群，而是“高价值、资料密集、交付压力强”的专业角色。

### GTM 主张

Codex 的主张是：把现代知识工作的瓶颈交给 agent。它不只说“更快”，而是列出非常具体的 work products：

1. Daily work brief。
2. Weekly summary。
3. Slide deck。
4. Research to decision memo。
5. File cleanup and reformatting。
6. Spreadsheet consolidation。
7. Book of business prioritization。
8. Month-end financial review。
9. Launch campaign kit。
10. Workflow audit and automation spec。

这套用例的核心不是“工具能力”，而是“我交给它一堆输入，它能变成可以评审的业务产物”。

### 官网内容组织

Codex 的内容结构很像产品化的 use-case library：

| 页面/模块 | 内容作用 |
|---|---|
| `Codex is becoming a productivity tool for everyone` | 把 Codex 从 coding 扩到 knowledge work |
| `Codex for every role, tool, and workflow` | 用插件、Sites、Annotations 讲团队级工作方式 |
| OpenAI Academy `How to use Codex for everyday work` | 直接给非代码用户 10 个 starter use case |
| Developers `Codex use cases` | 把 use case 按 workflow、team、task type 分类 |
| Productivity & Collaboration collection | 讲跨 app、文件、消息、文档、表格、可分享 artifact |

### 社媒栏目 / 标题风格

| 栏目 | 标题样本 | 内容打法 |
|---|---|---|
| First look / Introduction | `A first look at the Codex app`、`Introducing the Codex app` | 新产品教育 |
| Beyond coding | `Codex for Everyday Work: AI Agents Beyond Coding` | 把开发者工具翻译给知识工作者 |
| Build outcome | `Build beautiful frontends with OpenAI Codex` | 结果演示 |
| Customer outcome | `Advent Accelerates Deals with ChatGPT + Codex` | 用客户业务指标证明 |
| Role workflow | Launch campaign kit、Month-end financial review、Decision memo | 把 prompt 变成岗位任务 |

### 转化路径

Codex 的转化路径是：OpenAI 官方报告/文章 -> Academy webinar 和 starter prompts -> Codex 下载/ChatGPT 入口 -> role-specific plugins / Sites / annotations -> team adoption。它特别擅长把“非代码用户不懂 repo”这件事绕开，直接用 briefs、decks、workbooks、plans、process docs 作为入口。

### Kimi 可学 / 应避 / 可反击

| 类型 | 结论 |
|---|---|
| 可学 | 直接列“知识工作 starter tasks”，不要先讲功能名 |
| 可学 | 用 `work product` 而不是 `AI response` 证明价值 |
| 可学 | 把营销、财务、销售、研究、运营、投资这些角色单独做模板 |
| 应避 | 不要让 Kimi 看起来也需要工程环境、仓库、命令行、插件配置 |
| 应避 | 不要只讲“能生成 PPT/表格”，要讲从哪些 messy inputs 到什么 review-ready output |
| 可反击 | Codex 的非代码叙事刚展开，Kimi 可以更快占住中文办公和中文内容平台资料处理 |

## 4. Trae Work

### 产品定位

Trae Work 是从 TRAE SOLO 升级出来的 AI work assistant。它的公开叙事是：TRAE 不再只是 individual developers 的 end-to-end coding agent，而是面向真实 professional work 的 AI workspace。官方把产品族拆成 TRAE Work 和 TRAE IDE：TRAE IDE 深入软件工程，TRAE Work 横向覆盖 professional work。

### 核心功能

| 功能 | 表达方式 | 战略含义 |
|---|---|---|
| Work Mode | 研究、写作、数据分析、规划、协调 | 让非技术角色可以从需求和业务问题开始 |

## 5. Qoder Work

### 产品定位

QoderWork 是桌面 agentic assistant，官方主张是“bringing agentic capabilities beyond code”。它把 coding agent 的 autonomous planning 和 execution 移到普通桌面任务里，让用户用自然语言描述需求，QoderWork 规划、执行、交付结果。

### 核心功能

| Browser automation | 浏览网页、抓取信息、整理结果 | 适合 research 和竞品/用户反馈 |
| File / data / docs | 文件组织、数据处理、报告生成 | 非代码用户能直接理解 |

### 目标人群

QoderWork 的人群是 Operations、Marketing、Finance、HR、Sales、Legal，以及任何处理文档、数据和 deadline 的团队。它不像 Trae 那样偏产品构建，也不像 Claude 那样偏教育，它更像“桌面上的业务执行员”。

### GTM 主张
