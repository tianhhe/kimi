# Kimi 社媒增长工作台首页

更新日期：2026-07-02

这个首页是日常运营入口。打开它时，先确认本周要推动的不是“多发内容”，而是让 Kimi 被目标人群理解为一个复杂工作交付系统：能把真实任务、真实材料、真实行业问题，稳定变成可用结果。

北极星指标：社媒带来的 7 日内高价值任务完成用户数。

核心链路：目标 -> 人群任务 -> 场景卡 -> 内容脚本 -> 达人 brief -> 模板库 -> 数据复盘。

## 3. 使用顺序

### 每周怎么用

1. 周一上午：打开 `templates/weekly-review-template.md`，把上周结果先复盘完。
2. 周一下午：用 `docs/03-content-pillars.md` 和 `docs/12-kimi-platform-content-strategy.md` 定本周栏目配比。
3. 周二到周四：从 `docs/13-kimi-topic-bank-80.md`、`docs/14-first-batch-content-scripts.md`、`docs/19-platform-column-script-ops-manual.md` 取选题和脚本骨架，逐条写进 `templates/content-brief-template.md`。
4. 周三和周五：更新 `templates/creator-roster.csv`，对照 `docs/04-creator-campaign-playbook.md` 发达人 brief。
5. 周五：更新 `templates/growth-funnel-dashboard.csv`、`templates/platform-column-scorecard.csv`、`templates/competitor-tracker.csv`，只做三类决策：加码、重写、暂停。
6. 周内随手把评论区、私信和社群里的高频任务记进 `templates/comment-insight-log.csv`，不要只留在聊天记录里。

### 每月怎么用

1. 第一周：用 `docs/01-growth-masterplan.md`、`docs/02-goals-budget-metrics.md` 定月度目标、预算和主战场。
2. 第二步：用 `docs/23-kimi-audience-segmentation-v2.md` 和 `templates/audience-segment-matrix-v2.csv` 选本月 P0/P1 人群。
3. 第三步：用 `templates/month-1-content-calendar.csv` 或 `templates/month-2-content-calendar.csv` 建初稿，再按本月功能、节点和渠道资源调整。
4. 第四步：把本月必须验证的假设写入 `templates/experiment-log.csv`。
5. 月末：回到 `docs/16-growth-funnel-and-feature-usage.md`，按漏斗和功能使用率判断下月是否换人群、换栏目、换 CTA。

### 新功能 GTM 怎么用

1. 先用 `docs/05-gtm-checklist.md` 拆发布前 14 天、7 天、当天、发布后 3 天。
2. 再读 `docs/20-anthropic-site-content-system.md`、`docs/21-claude-site-content-system.md`、`docs/22-priority-sections-deep-read.md`，把新功能放进四层资产：Research 信任、Product 转化、Solutions 场景、Resources 教程。
3. 用 `docs/10-social-channel-title-swipe.md` 和 `docs/12-kimi-platform-content-strategy.md` 改成各平台可发布表达。
4. 用 `templates/feature-usage-tracker.csv` 定功能指标，用 `templates/growth-funnel-dashboard.csv` 追踪内容到功能使用的转化。
5. 发布后用 `templates/weekly-funnel-review-template.md` 单独复盘：是没人看见、看见不点、点击不激活，还是激活后没有完成高价值任务。

### 达人投放怎么用

1. 先用 `docs/23-kimi-audience-segmentation-v2.md` 判断要打 P0 还是 P1，不要先从达人报价开始。
2. 用 `templates/audience-segment-matrix-v2.csv` 把人群、核心任务、付费触发、平台、栏目和模板资产对齐。
3. 用 `docs/04-creator-campaign-playbook.md` 给达人分层、打分、设验收口径。
4. 用 `templates/creator-roster.csv` 管候选、报价、状态、下一步动作。
5. 用 `templates/creator-brief-template.md` 发 brief，要求达人呈现“真实任务 -> Kimi 介入 -> 交付结果”，而不是泛泛功能介绍。

### 复盘怎么用

1. 常规周复盘用 `templates/weekly-review-template.md`，重点看内容、渠道、达人、竞品、下周决策。
2. 漏斗专项复盘用 `templates/weekly-funnel-review-template.md`，重点看曝光、有效阅读/观看、互动、点击、任务开始、高价值任务完成、D7 复用。
3. 所有数据先进入 `templates/growth-funnel-dashboard.csv` 和 `templates/feature-usage-tracker.csv`。
4. 栏目层面用 `templates/platform-column-scorecard.csv` 判断是否保留。
5. 实验层面用 `templates/experiment-log.csv` 判断继续测、放大、停止或重写假设。
6. 研究层面用 `templates/research-to-content-pipeline.csv` 看哪些洞察已经变内容，评论层面用 `templates/comment-insight-log.csv` 看哪些问题还没有被资产化。

## 5. 当前工作台的默认规则

1. docs 里写判断和方法，templates 里写待执行和已执行。
2. 每条内容必须挂到一个人群任务，不单独为功能做内容。
3. 每个 GTM 都必须同时有内容包、站点/资源承接、功能使用率追踪。
4. 达人投放先看人群和任务价值，再看粉丝量和报价。
5. 周复盘不追求把所有数据都解释完，只输出下周的加码、重写、暂停。
